用 curl 给手机推送

脚本跑完、CI 失败、定时任务到点，发一条通知到你的 iPhone。点开通知还能打开一个链接，比如运行一个快捷指令。

拿到推送地址

在 iPhone 上打开 BaoCode，进入 设置 → 通知 → 用 curl 推送，点「开启」。下面会出现一条 curl 命令，点一下就能复制，里面的地址就是你的推送地址：

https://push.baocode.dev/v1/notify/<你的 key>

点「发一条测试」，收到通知就说明一切正常。不需要配对电脑，也不需要账号。目前只支持 iPhone：安卓版没有推送通道。

发一条通知

最简单的写法是 curl 的表单参数。--data-urlencode 会替你编码中文、空格和 &：

curl https://push.baocode.dev/v1/notify/<你的 key> \
  --data-urlencode "title=构建完成" \
  --data-urlencode "body=main 分支测试通过"

也可以发 JSON：

curl https://push.baocode.dev/v1/notify/<你的 key> \
  -H 'content-type: application/json' \
  -d '{"title": "部署失败", "body": "点开看日志", "url": "https://github.com/me/app/actions"}'

或者直接访问一个网址（GET），适合只能打开链接的地方。参数要自己做 URL 编码：

https://push.baocode.dev/v1/notify/<你的 key>?title=%E5%88%B0%E7%82%B9%E4%BA%86

参数

参数可以放在网址的 ? 后面，也可以放在 JSON 或表单请求体里；两边都写了的，以请求体为准。

参数含义
title二选一标题，最多 200 个字。
body二选一正文，最多 1000 个字。title 和 body 至少要有一个。
url可选点通知后打开的链接：网页（https://…），或其他 App 的链接（shortcuts://…、weixin://……）。最多 2000 个字符。
group可选分组名，同组的通知在通知中心里叠在一起。最多 64 个字。
replace可选替换标记：新通知会顶掉之前带同一个标记、还没看的那条，适合报进度。最多 64 个字。

点开通知运行快捷指令

把 url 设成快捷指令的链接，点通知就会运行它。比如先在「快捷指令」App 里做一个叫「给妈妈发微信」的快捷指令，再：

curl https://push.baocode.dev/v1/notify/<你的 key> \
  --data-urlencode "title=该给妈妈发消息了" \
  --data-urlencode "url=shortcuts://run-shortcut?name=给妈妈发微信"
  • 点通知会先打开 BaoCode，再马上跳到目标 App。iOS 不允许收到通知时自动执行，必须由你点一下。
  • 第一次遇到某一种链接（比如 shortcuts://），BaoCode 会问你是否允许。允许后，同一种链接以后会直接打开。网页链接不会问。
  • 快捷指令里有些操作（比如发消息）iOS 自己还会再让你确认一次。

在快捷指令里发推送

用「获取 URL 的内容」操作：URL 填你的推送地址，方法选 POST，请求体选 JSON，加上 title、body 等字段。配合「自动化」就能在到家、充电、打开某个 App 时提醒自己。

返回结果

状态码含义
200{"ok":true}：苹果已经收下，通常几秒内送到。
400参数不对，error 里写了原因。
404没有这个 key：可能已经重置过，换成 App 里显示的新命令。
410手机上的 BaoCode 已经删掉或重装过。重新打开 App，key 会自动恢复。
429太频繁：每个 key 每分钟最多 30 条。
502苹果拒收了，error 里是苹果给的原因。

安全与隐私

  • 谁拿到了 key，谁就能给你的手机发通知、让你点开他设的链接。别把带 key 的命令贴到公开的地方。泄露了就在 App 里点「重置 key」，旧 key 立刻失效。
  • 推送经 push.baocode.dev 转给苹果的推送服务（APNs）。服务端只存 key、手机的推送地址和一个校验用的哈希，不保存推送的内容。
  • 超过 180 天没打开过 BaoCode 的 key 会被删除；再打开 App 就会恢复，key 不变。
