更新日志

BaoCode 每个版本的变化。

1.0.5

新功能

  • 新增网络设置：使用系统代理、手动指定代理或直接连接。可同时测试多个网站的连接，查看响应时间和连接失败的原因。
  • 新增两种内置通知音效：man-oh-yeah 和 Gulp Gulp Gulp Gulp。

改进

  • 界面文字缩放与代码字号分开控制：编辑器和侧边面板的代码视图遵循代码字号，对话文字与界面标签遵循界面缩放；字体设置修改后立即生效。
  • macOS 和 Windows 的通知音效及试听支持重叠播放，不再打断上一段声音。
  • 菜单与窗口四周保持 8px 安全边距，过长的列表在菜单内部滚动。

修复

  • 改善编辑器和侧边面板中长 diff 的滚动流畅度，修改行很多时也不再卡顿。
  • 修复对话内容组件变化时，文字选择被干扰的问题。
  • 修复拖动经过对话宽度设置时，意外改变设置值的问题。

1.0.4

改进

  • 源代码管理和侧边面板的“变更”页不再因为改动太多而卡死（比如把整个用户主目录建成了 Git 仓库）：最多显示前 10,000 项并给出提示，这时文件变化不再自动刷新，需要时手动刷新；滚动和拖动滚动条也保持流畅（#6）
  • 查看大文件或整体改过的文件的 diff 时不再卡住：diff 编辑器、侧边面板的 diff 预览和行内 blame 都改在后台计算
  • SSH 远程项目同样受这个上限保护，改动很多时不再通过 SSH 传回全部 Git 状态
  • 语言服务器的文件监听跳过 Git 对象和 node_modules 里的包文件，文件大量变化时分批处理，不再拖慢窗口

新功能

  • 侧边面板的“变更”页能识别子文件夹里的 Git 仓库，和源代码管理一致；有多个仓库时可以切换

修复

  • 智能体的目标（/goal）状态不准：放弃或出错结束的目标被当成已完成，恢复会话后也会判断错；没有任务在推进时，目标的计时仍在走
  • 对话里拖动选择文字，有时一直选不中，直到重启应用
  • 有排队消息发出或状态更新时，对话里的文字选择会出错
  • 使用 DeepSeek、智谱、阿里云等提供的 Anthropic 兼容接口时，模型列表现在能正常列出

1.0.3

Windows 上 1.0.2 打不开？

  • 如果 1.0.2 一启动就自己退出、没有窗口，应用内的自动更新也就没法用，请从 https://baocode.dev/download 下载 1.0.3 直接安装，会覆盖原来的版本，设置和对话记录都会保留。

修复

  • Windows：部分电脑上 1.0.2 启动后立即退出、不显示窗口（系统里的 Visual C++ 运行库版本较旧时会这样）。现在应用自带所需的运行库，不再依赖系统里装的版本
  • Windows：用 Volta 安装的 Claude Code 无法启动、提示命令无法识别的问题已修复

1.0.2

自动更新没装上？

  • 如果点了“立即重启更新”后应用关闭，再打开还是旧版本（1.0.0 和最早发布的 1.0.1 可能会这样），请从 https://baocode.dev/download 下载 1.0.2 直接安装，会覆盖原来的版本，设置和对话记录都会保留。

新功能

  • 设置 → 外观：可以设置代码字体、字号、连字和界面文字大小，边调边预览；终端也使用这里的字体和字号
  • 在输入框里粘贴很长的文本时，会收成一个标签（如“粘贴的文本 #1 +120 行”），不会再让窗口卡住；鼠标悬停可以预览，发送时完整内容随消息一起发出

1.0.1 的新功能

  • 对话旁边的侧边面板：浏览项目文件，查看、暂存和提交 Git 改动（提交信息可以让 Claude 起草），打开终端和智能体在后台运行的命令
  • 在侧边面板里查看 Claude 改过的文件，可以直接编辑、保存
  • 工作区：把几个文件夹放在一起，智能体同时在这些文件夹里工作；文件夹里嵌套的 Git 仓库也能识别
  • 在输入框里用 @ 引用别的对话；侧边栏里智能体的菜单可以复制会话 ID
  • SSH 远程项目支持 macOS 主机
  • 对话和 Markdown 文件里的 Mermaid 图表直接画成图，不用联网，可以放大查看
  • 显示智能体的计划卡片；对话栏的宽度可以在设置里调整
  • 资源管理器里可以复制、剪切、粘贴文件
  • 侧边面板里，后台命令的输出用真正的终端显示：终端的字体、颜色、选择、查找和链接

1.0.1 的改进

  • 第一次使用时自动跳过 Claude Code 的初始引导；找不到 Claude Code 时会直接说明
  • 再次打开文件时代码高亮立即显示，不用等它重新着色
  • 窗口较窄时，侧边栏和侧边面板只留最后打开的那个
  • Windows：新安装默认只为当前用户安装，安装和自动更新都不再需要管理员权限；需要时仍可选择为所有用户安装
  • 自动更新更可靠：Windows 上需要管理员权限时，确认窗口出现在最前面；更新没装上时，下次启动会提示，并给出下载页和安装日志
  • 跳过的版本在侧边栏仍会显示“更新”按钮，只是不再弹出提醒
  • 出错信息、Windows 的窗口日志和卡死报告都记录在数据目录的 logs 文件夹里，方便排查问题
  • 交互面板里显示返回的快捷键

1.0.1 的修复

  • 在 Dark 2026、Dark Modern 等主题下，对话里命令的程序名、字符串和参数看不见
  • 在浅色主题下，对话里的命令和输出颜色太浅，现在和终端一样保证对比度
  • 项目图标选了青色或洋红色时，在部分主题下不显示颜色
  • 移动数据目录时如果有文件被其他程序占用，会指出是哪些文件，而不是只报复制失败
  • 建议的提示词里带反斜杠（如 Windows 路径）或换行时，输入框会变成灰色的错误块
  • Windows：显示器休眠后，或窗口隐藏时改变了大小，窗口内容会卡住不再更新
  • Windows：在第二块屏幕上最大化的窗口从最小化恢复后，没有铺满屏幕，也不响应输入
  • 打开“自定义”页面时，侧边面板的侧栏仍然显示
  • Windows：“关于”窗口里的版本号不对，图标也不是应用的图标

1.0.0

BaoCode 的第一个版本：Claude Code 的桌面应用，内置快速的 IDE。支持 macOS（Apple 芯片和 Intel）和 Windows。

对话

  • 执行步骤折叠成一行，当前任务和进度固定显示在输入框上方
  • 按文件查看 Claude 做的修改，逐个保留或撤销；检查点不会碰你仓库的 .git
  • 用 /goal 给 Claude 设定目标，它会一直工作到目标达成
  • 富文本输入框：粘贴图片、拖入文件，从编辑器复制的代码会变成对文件和行号的引用
  • 可以编辑已发送的消息、搜索历史对话，查看上下文和套餐用量
  • 多个智能体并排运行，可以放在标签页里，也可以各开一个窗口
  • 可以设置 Claude 写的提交和 Pull Request 里的署名

SSH 远程项目

  • 通过 SSH 打开 Linux 主机上的文件夹，体验和 VS Code 的 Remote-SSH 一样：窗口留在本机，文件、搜索、Git、终端、语言服务器和 Claude Code 都在远端运行
  • 从 ~/.ssh/config 里选主机，或者直接输入 user@host
  • 远端没有 Claude Code 时会自动安装，本机配置的模型在远端也能用
  • 断线自动重连；连不上时会说明原因，可以一键重试

Fast IDE

  • 编辑器、终端，以及带提交图和 Git 追溯（blame）的源代码管理
  • 沿用你的 VS Code 主题、快捷键和语言服务器
  • Markdown 文件以预览方式打开，可以像 Typora 一样直接在预览里编辑
  • 提交信息由 Claude Code 起草，你修改后提交

模型与扩展

  • 通过 Claude Code 使用其他模型：支持 Anthropic API、OpenAI Chat Completions 和 Responses，API 密钥保存在系统钥匙串里
  • 可以为 Claude Code 的各类工作分别选择模型，标题和提交信息也可以单独选
  • 插件、MCP 服务器、技能、子代理、规则、命令和钩子集中管理，claude.ai 上的技能也会同步过来

其他

  • 智能体需要你时，有系统通知、提示音和应用图标上的数字提醒；关掉窗口后，智能体仍在菜单栏或托盘里继续运行
  • 可以从访达或资源管理器直接用 BaoCode 打开文件夹，窗口也可以置顶
  • 支持中文和英文界面
  • 在后台自动更新，重启前会先询问
