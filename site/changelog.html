Changelog

What changed in each version of BaoCode.

1.7.0

New Git View

This release is all about a new Git view. The old Changes panel is replaced by a JetBrains-style Git log and Commit panel. Your everyday Git work happens in BaoCode, with AI ready to help: committing, branches, rebases, conflicts, stashes and comparisons. Besides, Windows now has a native Arm64 build, projects in WSL open directly, and BaoCode uses much less CPU on macOS.

New Git view

  • Git log: the commit graph and branch and tag labels look as they do in JetBrains IDEs. Filter by branch, path, user or date, select several commits, and see the history of a file, a folder or a few lines. A branch tree beside the log has the branch actions.
  • Commit panel: tick the files to commit, with no staging first. A tick box by each change lets you commit only some lines of a file. Each turn of an agent goes into a changelist of its own, and you can make your own changelists.
  • Commit options: Amend, the author, Sign-off and whether to run Git hooks. Ctrl+M brings back earlier commit messages. While you write a message, its subject length and blank line are checked. Unversioned files can be added to .gitignore, and ignored files can be shown. A commit message can be written from the ticked changes alone.
  • AI review before committing: turn it on, and AI looks over the ticked changes before they are committed. If something is wrong, the commit waits for you.
  • Ask AI: about a commit in the log, or about changes and conflicts in the Commit panel. The request is put in the chat's input for you to look over before sending it. A button by a change in a diff puts that change, with its file and line, in the input.
  • Branches: the branch popup in the status bar creates, checks out, merges, rebases and compares branches. Push has its own dialog. Update Project lets you choose merge or rebase.
  • Rebases and conflicts:
    • Interactive rebase, Clean Up with AI to tidy commits, and Fixup.
    • A merge, rebase, cherry-pick or revert under way shows on top of the panel, with Continue, Skip and Abort.
    • A conflict can take one side in a click, open in a three-way merge dialog, or be merged by AI.
  • Stash: stash and restore changes, in a Stash tab as in JetBrains IDEs.
  • Remotes and repositories: manage remotes, and push tags to a remote or delete them there. Clone a repository from the start page.
  • Worktrees: the IDE's Source Control can show another worktree. The branch menu under the chat's input creates and switches worktrees, and the log shows which worktree the AI is working in.
  • Comparing:
    • Compare a file with a branch, a revision, the clipboard or another file.
    • Compare two folders, or compare a branch with the current one by its commits.
    • Diffs can collapse unchanged parts and ignore all whitespace.
    • An arrow in an editor's diff tab reverts that change. The agent's changes are marked in diffs.
  • Editor:
    • JetBrains-style change markers by the line numbers, and Annotate with Git Blame.
    • New local history: each saved file keeps its versions for a week. Show Local History compares one with the file, and arrows take changes back.

Windows on Arm and WSL

  • A native Arm64 build for Windows (BaoCode-1.7.0-setup-arm64.exe) runs natively on Snapdragon and other Arm PCs. Its updates come as Arm64 too. The download page has an Arm64 button.
  • Open projects in WSL distributions. Open Remote Project lists this machine's distributions. Files, Git, terminals, language servers, Claude Code and reconnecting all run inside WSL, and the status bar says "WSL: ".
  • Inside WSL, the Claude Code installed on Windows is no longer used by mistake. It failed with "Settings file not found: E:\dev\shm\…"; now BaoCode offers to install one in WSL.

Performance

  • Much less CPU on macOS.
    • Windows where nothing changed, and the hidden Stash panel, are no longer drawn at every frame. While an agent runs, drawing a frame takes 1–2.5 ms instead of 6–11 ms.
    • Loading animations step together at 30 frames a second rather than each on its own. The IDE and the sidebar rebuild only when what they show changes.
  • Git and checkpoints run in the background and no longer hold up the interface. A check when nothing changed runs 3 Git commands instead of 13.
  • Changes in ignored folders such as build and node_modules no longer refresh the Git status. The model lists are worked out once.

Other new features

  • Settings → Appearance has a Native Window Blur switch for the system blur under the windows on macOS and Windows 11. It is off by default.
  • Word wrap in the editors: turn it on in Settings → Appearance, or toggle it with Alt+Z in an editor.
  • Full screen, from the View menu or F11 (⌃⌘F on macOS).
  • Sidebar:
    • Pin projects to the top. Collapse or expand all projects at once.
    • Edit a project's name and location; its conversations move along.
    • Hovering over a conversation shows the model it uses.
  • Find in the editor and Search both match across lines, and multi-line text pasted keeps its line breaks. Search keeps its files to include and exclude, and its options, across restarts.
  • Set up a language server of your own from Open Language Server Settings. It takes effect when saved, with no restart.
  • Background tasks that ended can be cleared, one at a time or all at once.
  • When the built-in core's agent ends its work with to-do items still open, the model is reminded to update its list.

Fixed

  • The conversation minimap appears only once a conversation is long. Early on, it no longer comes and goes as you expand and collapse steps.
  • Switching files in the Git log, or changes in the side panel, no longer flashes.
  • After a rebase finishes, the Commit panel no longer keeps showing "Rebasing". Continue no longer fails with "Cannot continue the rebase".
  • A WSL or SSH project removed from the list no longer comes back when you open another project on the same host.
  • Files a subagent changes show in the review as they change. Its changes outside the project can be seen and undone. In a project opened through a link, files are no longer taken for files outside the project.
  • With another upstream, availableModels in Claude Code's settings no longer swaps your model for a Claude one.
  • A plan sent to you rather than written to a file now shows as a plan card, ready to start.
  • A code block ends at its closing fence; the rest of the reply is no longer shown as code.
  • Linux plays notification sounds and shows desktop notifications.
  • On Chinese Windows, the output of a failed MCP command is no longer garbled. MCP servers that refused BaoCode's connection check with HTTP 415 now accept it.
  • Typing with an input method over selected text replaces the selection.
  • On Windows, the title bar over Settings shows only the window's buttons.
  • On macOS, the app launched from the Dock or Finder can hold more than 256 open files. With many agents, terminals and language servers open, Claude Code failed to start with "Too many open files".
  • A remote folder that failed to load on the first connection loads again once a retry connects.

1.6.0

Performance

This release is about speed and memory: in a long conversation, a reply streaming in, scrolling and dragging the minimap all keep up with you; the app holds much less memory as it runs; and on Windows the interface draws several times faster. Besides, Stash keeps in step with your projects' GitHub / GitLab issues, and an SSH connection that drops picks up the same session again, with nothing running there lost.

Performance

  • Windows draws with Skia, as macOS does, not Flutter's new default Impeller: measured, a frame of the chat takes a fraction of the time to draw, in about half the memory.
  • Long conversations stream more smoothly: each file path in a reply is no longer looked up in every file the session has read. On a real 92-turn conversation, a frame went from 6.8 ms to 4.5 ms, and janky frames from 18 to none.
  • Very long replies and thoughts let go of what is far out of view, keeping only its height, and show it again as it comes back; a thought draws only what is in view; code, tables and math scrolled sideways are kept as pictures. Select All and copying still get all of the text.
  • Dragging the minimap or the scrollbar fast no longer builds what is out of view meanwhile, catching up over a few frames after; a reply scrolled away and back is not parsed again. Dragged back and forth fast, a frame went from 12.9 ms to 2.5 ms.
  • Less memory: Skia's texture cache is held to 32 MB rather than 150 to 300 MB, and decoded images to 48 MB; on macOS large blocks freed go back to the system, some 180 MB while a long thought streams.
  • Leaner editors: files of the same language share one syntax highlighting worker, its patterns compiled once (TypeScript's 334 were compiled in some 3,500 places), and line layouts are held to about 32 MB.
  • In plan mode the prompt cache is read again: each turn wrote the whole conversation to it anew, slower and dearer.
  • A trackpad flings the editors on as it does lists; on macOS lists no longer bounce at their ends.

New

  • Stash and issues, both ways: in a project that is a GitHub / GitLab repository, open issues become stashes, one row each with its status, title, conversation and issue. Kept in step: changed there, taken here; changed here, pushed once you confirm; changed on both sides, yours to pick; an issue closed, its stash is done. Every open issue by default; Settings → Stash → Issues as stashes keeps it to yours, or off.
  • Stash news: new comments on an issue, one closed or reopened, a linked pull request's checks failing, changes asked for, merged: each marked on its row, and those about you counted beside Stash in the sidebar. A pull request failing or asked for changes is fixed in its conversation in a click; a merged one asks whether the stash is done.
  • A stash can be published as an issue: what goes is shown first, local paths and secrets pointed out, local pictures uploaded with it. Merging stashes can close a merged one's issue as a duplicate.
  • A new markdown editor: stashes, markdown previews in the side panel and the chat's input are edited as they read, the marks showing only where the caret is. Tables are edited in their cells: rows and columns added and removed, cells picked, copied and pasted as in a spreadsheet; a link shows a bubble to open, copy, edit or remove it.
  • Customize: skills, rules, commands and subagents open in the markdown editor, edited as they read or as their source; front matter shows as properties, edited as a form.
  • SSH drops lose nothing: after a network hiccup the connection goes back to the same session, its terminals, Claude Code and language servers still running there (kept up to three hours while disconnected), no output lost or repeated; a silent network is noticed within 30 seconds.
  • Going on after the usage limit: on Claude's own account, the model picker has Continue After Limit Reset. On, a conversation stopped at the limit goes on once it resets, even with the computer asleep past it; one due while the app was closed goes on as it opens.
  • The Claude Code CLI, recommended: where Claude Code is installed it is the core by default; a conversation on the built-in core suggests switching, above its input, downloading the CLI in a click, or Not Now.
  • Models: subagents and the Opus / Sonnet / Haiku tiers can use another upstream's models; a model can have its own endpoint (Anthropic, Chat Completions, Responses); an upstream or a model is duplicated in a click; models an upstream no longer lists are removed at once.
  • The minimap: each of your messages is a clear mark on it. The pointer near one snaps to it and shows at once the message and the replies around it; a click goes there.
  • The input: a / starting any word opens the command menu; a command's tag shows its whole description on hover, and Open details opens its file in the side panel. @ finds folders too. File, folder and code chips in the input open what they name.
  • While the agent works, Enter in the empty input sends the first queued message now; background tasks (subagents among them) keep going.
  • A changed file's right click opens it in the browser (HTML), its default app or another editor, shows it in the file manager, or copies its path.
  • The side panel's markdown preview takes pictures and files dropped or pasted in, copied beside the document and linked; a right click shows a link's file in the file manager.

Fixed

  • A conversation switched away from and back to is where you left it, its steps still open.
  • A conversation renamed in Claude Code (/rename) is renamed in the list.
  • With "viewMode": "verbose" in Claude's settings, Stash's polish, the input's polish and commit messages no longer fail.
  • A single ~ (a range such as 10-12~10-16) no longer strikes text out.
  • The markdown preview fills the view, wide tables no longer cut off; zoomed in, a drag in it selects under the pointer.
  • With the side panel at the left and the sidebar hidden, its tabs keep clear of the traffic lights on macOS, and the sidebar's toggle is there too; dragging its edge follows the pointer from the width shown.
  • Go to Definition in a remote project opens the right file on its host.
  • Windows: updating or uninstalling ends the browser extension's host first, no longer failing with "DeleteFile failed; code 5".

1.5.0

Easy SSH

Connecting to a server no longer starts with setting up ssh in a terminal: type its address in BaoCode and connect, with the password, key and jump host in one form, and no terminal to accept the server's key the first time. Settings has a new SSH Servers page, where all your servers are kept, each with the core it runs.

New

  • Add an SSH server: Add SSH Server… in the list of remote projects asks for the host, port and user, and how to sign in: a password, a private key, or Automatic (as ssh does in a terminal). A pasted user@host:port is split up, the keys in ~/.ssh are offered, and a password is kept in the system keychain. Saved, it connects in one click; a failed connection's page and the sidebar edit it too.
  • Jump hosts: pick a saved server to connect through, each asking for its own password.
  • A server connected to for the first time has its key remembered by itself. One whose key changed is told as such, and once you know it was reinstalled, its old key can be removed to connect again.
  • Settings → SSH Servers: the servers added in the app and the hosts the sidebar has used, to edit, connect, disconnect or remove; the hosts of ~/.ssh/config are listed apart, their file a click away.
  • A core for each server: Automatic (the server's Claude Code CLI if it has one, else the built-in core), the built-in core, or the Claude Code CLI (installed there if missing). Remote hosts no longer follow this machine's core setting.
  • Passwords on Windows 10: the installer carries a recent OpenSSH, used where the system's is too old or missing.
  • Settings → About: the version, the site, the changelog and the issues, and a way to star BaoCode on GitHub. Accounts is now Git Accounts.
  • The browser extension works on Linux, in Chrome, Chromium, Edge, Brave and Vivaldi.
  • A file another tool asks BaoCode to open as file:line:column (a front-end inspector's Open in Editor, say) opens at that line and column.

Improved

  • Typing in the IDE is smoother: an edit goes through only the lines it changed, the input method is given only the lines around the caret, and typing no longer redraws the whole IDE.
  • Switching chat tabs in the IDE is faster: the chats seen last are kept, shown again at once where you left them.
  • Changes in the side panel open in the IDE's diff editor: the deleted code in the text where it is narrow, side by side once wide enough, with the overview of the changes at the right, and long files no longer slow it down.
  • The live time, speed and tokens under a reply while the agent works are one switch now (Settings → General).
  • Through OpenCode's gateway, the requests of a conversation hit its prompt cache: faster, and cheaper.
  • The model menu opens scrolled to the model in use.

Fixed

  • A picture zoomed in the preview is no longer clipped to its first size.
  • Generated images, screenshots and pictures read stay in a conversation switched away from and back to.
  • After switching to another provider's model mid-conversation, messages go to the model picked; with the model in use removed, the one the picker shows is used rather than "Not logged in".
  • Go to Definition (F12) centers its target, even one already on screen.
  • Windows: zoomed in, the title bar's buttons are clickable all the way to their right edge; installing language servers no longer fails with "not a valid Win32 application".
  • The file manager is called by each system's own name (Finder, File Explorer…).

1.4.0

Hello, Linux

BaoCode runs on Linux now: a package for Ubuntu and other Debian-based distributions, x64 and arm64, that keeps itself up to date like the Mac and Windows apps. And setting up a model the first time is a welcome rather than an error.

New

  • Linux: download the .deb for your processor from baocode.dev/download (Ubuntu 22.04 or later, and other Debian-based distributions). It opens folders and files with the system's dialogs, has the system's right-click menus, and pastes text, files and pictures. Thanks to qyh1221, whose port this is.
  • Linux updates itself: a new version is downloaded and checked as on the other systems, then installed once you enter your password, and BaoCode opens again. A copy run from the tarball is pointed to the download page instead.
  • Setting up a model: with no model to run on yet (BaoCode's own core, before any upstream is added), a welcome explains what an upstream is and adds one in a click, opening its page in Settings → Models. The conversation starts by itself as soon as a model is there, with no retry. Until then, Set Up a Model sits in the model picker's place under the input, and in the command palette.
  • From your phone, Start on a plan the agent put to you starts it, as the desktop's button does.

Improved

  • An upstream's models are listed by name, in its settings page, the fetched list and the model picker.

1.3.0

Good Friends with Chrome

This release is about the browser: agents can use your own Chrome now, opening pages, clicking, typing and debugging with your sign-ins, every step of it in view in the side panel. Agents can also make pictures with your upstreams' image models, and pictures show right in the chat. BaoCode has a core of its own; an agent's changes can be reviewed part by part beside the chat; long conversations open faster, and the mouse wheel keeps up with your hand. And a batch of problems is fixed.

New

  • The browser: add the BaoCode extension (from the Chrome Web Store, or as a zip loaded unpacked) and agents can open pages, read them, click and type in your own Chrome, Edge, Brave or Arc, signed in as you are. They touch only the tabs you share with them (the BaoCode button in the browser's toolbar shares the tab you're on). The side panel shows the page they're working in as it happens, and you can work in it too. Turn it on or off and install it in Settings → Browser, on macOS and Windows.
  • Debugging in the browser: agents read the console and network requests, set breakpoints and step through code, see variables by their source-mapped names, find a page's React and Vue components and event handlers, look into performance, memory and unused CSS, block, mock and rewrite requests, and run a tab as on a phone or a slow network.
  • A debugging history of the browser: the pages, requests and console errors and warnings of the tabs you share are kept as they happen, with no recording to start. Say "saving just failed" and the agent looks it up itself. Detailed history keeps request and response bodies too, and your clicks and typing (never passwords). It stays on this computer; Settings shows how much room it takes and clears it, and you're told once it passes 1 GB.
  • Show the agent how: an agent can ask you to do something once in the browser, keep each step as a file in the project, and do it again in your browser later.
  • Making pictures: agents generate images with your upstreams' image models (the Images API, chat interfaces such as OpenRouter's and Gemini's, Codex's gpt-image-2). Pick the default image model in Settings → Models, or Ask each time to choose in the chat; image models stay out of the chat's model picker.
  • Pictures in the chat: what a tool returns as a picture (an image file read, a browser screenshot, an MCP tool's image) and local images in a message show in the conversation. Click one to see it whole, and ← → go through every picture in the chat; right-click to open it in the side panel or the IDE, copy its path or show it in Finder. Image files open in the side panel too.
  • The built-in core: BaoCode's own Claude Code core, with CLAUDE.md, skills, subagents, commands, hooks, plugins and MCP servers, on remote hosts too. Switch in Settings → General → Claude Code → Core: the CLI where Claude Code is installed, the built-in core otherwise. The built-in core uses only the upstreams added in Settings → Models; pick the CLI for a Claude subscription.
  • Reviewing changes beside the chat: the side panel's editor shows an agent's pending changes in the code, as the IDE does, each part to undo or keep on its own. The bar above goes to the previous and next change and keeps or undoes a file, or everything at once. The side panel's editor finds and replaces too.
  • Live usage: while an agent works, the time so far, the writing speed and the tokens roll by under the status line; a finished turn shows its time, speed, cost and tokens, still there when the session is opened again.
  • The status line's musings are now mostly about the step just done, its command or file by name.
  • Polish in the composer: the button beside the context ring has the model tidy your words, keeping tags, images, code and paths as they are, and it can be undone. Turn it off in Settings → General if you don't need it.
  • The side panel can move to the conversation's left: the button in its bar, or Toggle Side Panel Position in the command palette and the View menu.
  • Settings → Appearance → As a Reply Comes: Stay at its start stops following once your message reaches the top, so you read the reply from its beginning.
  • Settings → General turns off Suggest Next Prompt, saving the extra request each turn; Settings → Appearance hides the times in the sidebar.
  • The + on the Stash page starts a new note right there on the right, ready to type in.
  • Diagnostics: an event log of windows, views and the theme goes with the diagnostics uploaded from Settings → Updates, to track down windows that stop responding.

Improved

  • A long conversation is read from its end, the earlier turns as you scroll to the top: it opens much faster. A very long turn loads a page at a time too.
  • The mouse wheel glides, eased and close behind your hand, in the chat, file trees, lists and editors, high refresh rate screens included. Trackpads are as they were.
  • Checkpoints keep only the files an agent edited instead of snapshots of the whole project, which could take gigabytes; old checkpoint repositories are deleted, and a session's checkpoints a month unused are tidied away.
  • Several thoughts in a row show as one.
  • Messages sent while an agent works: queued ones are taken one at a time, and one sent now goes alone.
  • Usage statistics: one anonymous ping a day, holding only a random install ID, the version, the operating system and the processor; the Send Usage Data switch is gone from the settings.

Fixed

  • Another model or upstream picked while a task runs takes the next message, instead of the one before.
  • In a remote project, files from this computer dropped into the composer are copied to the remote host first.
  • Networks listed in NO_PROXY (such as Tailscale's 100.64.0.0/10) go around the proxy, and are passed on to Claude Code too.
  • The main window opens where it was left, as big, maximized if it was.
  • Windows: back in the window after Alt+Tab, the first key types and the window keeps drawing; waking from sleep is no longer taken for a hang.
  • macOS: closing a window in full screen no longer leaves a black Space.
  • Terminal: functions bash exports (environment modules' module and ml) reach the terminal whole.
  • The explorer shows a symbolic link as what it leads to, in remote projects too.
  • Stash: a note an agent writes on Windows shows without a restart; the page's filters stay as you last set them; clicking a card's conversation opens the note.
  • Sidebar: an agent opened from elsewhere, a new one included, is the one selected; with Stash or Customize shown, the earlier conversation isn't highlighted as well; what has no room gives way instead of being pushed out of its row.
  • A subagent continued opens from its row above the composer and goes on in its own card.
  • Conversations side by side each have their own side panel bar.
  • And smaller fixes: Tab takes the suggestion past an empty IME composition; a table's scrollbar shows again alongside the minimap; inline tags sit centered on their text; a message's editor gets all its room; the Customize details' buttons sit flush right; a link to a heading with a % in it opens.

1.2.0

Meet Stash

A big release. Stash is new: jot down ideas, screenshots and links from any app, hand them to an agent when they're ready, and see how each one is going at a glance; sign in to GitHub or GitLab to import issues into it and keep issues and pull requests up to date. The phone app's beta is now on the download page. Git, the Fast IDE, remote hosts and model settings gain a good deal more, and a long list of problems is fixed.

New

  • Stash: an inbox for whatever comes to mind. Set a global shortcut in Settings → Stash and press it in any app to bring up a floating panel and note something down (none is set by default, so as not to clash with other apps). Text, screenshots, files, links, code, tables and formulas all go in, and each note has its own number, like an issue.
  • Keeping Stash tidy: pin notes, drag them into order, filter by time, project and status, and merge duplicates; search finds text inside images too, and AI search finds notes by meaning.
  • Handing a note to an agent: click Implement in BaoCode and choose a new git worktree or the current branch, or @ the note in a chat. The chat and the note are linked, and the note's card shows how the chat is going.
  • AI to say it clearly: Polish smooths the selected text, and Clarify turns a one-liner into a full request, using its images and attachments; both can be undone.
  • Accounts (Settings → Accounts): sign in to GitHub or GitLab, in the browser or with a token, GitHub Enterprise and self-hosted GitLab included. Issues and pull requests linked from Stash show their latest state and checks; import issues from your projects' repositories, and reply to or close an issue once you've confirmed, with a warning first if the text looks like it holds a local path or a secret. Tokens are kept only in this computer's keychain.
  • The phone app (beta): download it for Android or iOS from the download page, pair it with your computer, and follow and steer its agents from your phone.
  • Phones through a Cloudflare Tunnel: write the public address in Settings → Mobile as wss://your-domain, and leave the domain's Always Use HTTPS on.
  • Branch bar: the current Git branch over the chat, to search, switch and create branches; a workspace of several folders lists each folder's branch. Switching waits while an agent runs, so as not to pull the ground from under it.
  • In plan mode, the plan's card has a Start button: leave plan mode and get going on the plan in one click.
  • Each chat picks its own model; Codex's Fast tier has moved there, and both Responses and Codex upstreams support Fast.
  • Find in Chat (⌘F / Ctrl+F), and Paste as Plain Text (⇧⌘V / Ctrl+Shift+V).
  • Settings → Appearance → Interface Size scales text, icons and spacing together; the terminal's text follows it, or takes a size of its own.
  • Settings → Customize: create, edit and delete project and global rules, skills, subagents, commands, MCP servers, hooks and plugins right in the settings.
  • Custom request headers for each upstream in the model settings, with the session ID and model name available as variables.
  • Git: fetch, pull and push; pick the repository in a project with several, with submodules as repositories of their own; the graph can show every branch, names each commit's branches and tags, and lists a commit's files as a tree.
  • Files: search the whole project's text from the side panel; open a file link from a chat in the side panel, preview it or open it in the browser; Open in Terminal in the explorer, and choose which files and folders it hides in the settings.
  • Fast IDE: turn on Show agent changes as diffs to have each file an agent changes open as a diff as it goes; change a file's language mode by hand; format JSON and other files without a language server.
  • Remote hosts: the host indicator in the status bar has a menu, and files on a remote host open directly over SSH, with the ones opened lately listed.

Improved

  • The sidebar's agent list is rebuilt, with multi-selection to pin, archive and delete several at once; archived agents can show in the IDE too.
  • The Fast IDE opens in the main window by default, in place of the chat; switch back to a window per folder in the settings.
  • An earlier conversation shows that it's loading while it opens, and very long conversations run more smoothly.
  • The subagents and background tasks running show over the composer, a click away.
  • Quick Open in a remote project waits on neither the connection nor the ranking.

Fixed

  • A queued message taken back to edit lands in the composer instead of being lost, and one sent now ahead of the rest is no longer lost either.
  • A project folder that has been deleted or moved is reported in the app's language.
  • The model providers' keys come along when the data folder moves.
  • Claude Code's own models are always listed, and kept between runs.
  • A key the base URL refuses is reported, rather than left as an empty list.
  • The window buttons' place, the editor's icons, trackpad scrolling, and list selection and highlighting match the IDE's in many small ways.
  • And a batch of smaller fixes: text typed into a URL jumping about, the model's name cut short in a narrow composer, saves of one Stash note overwriting each other, and more.

1.1.0

Nice and bouncy

This release lays the groundwork for your phone: BaoCode on a phone can pair with your computer, to see and steer its agents. The conversation also has a minimap, so a long one can be taken in at a glance and any part of it reached with a click; under each reply there is now a copy button and what the turn used.

New

  • Phones (preview): a new Settings → Mobile page. Pair a phone by scanning a QR code, or let a phone on the same network find the computer; both sides show a security code to check, then they connect directly over the local network or the internet, end-to-end encrypted, and keep working when the computer's IP changes. Off until you show the QR code; the first time, macOS asks whether BaoCode may use the local network. The phone app is coming soon.
  • Conversation minimap: a miniature of the whole conversation beside it, your messages, code, tables and changes each telling apart. While you scroll, a drop of liquid glass marks where you are, magnifying what is under it a little, like the macOS Dock; click or drag it to go anywhere.
  • While the minimap shows, it takes the place of the scrollbar on the right, and the messages leave a little more room either side; in a narrow window it hides and the scrollbar is back.
  • Settings → Appearance: turn off Conversation Minimap to keep the scrollbar on the right, as before; with it on, set how opaque its glass is (0% to 150%), and how much it stretches as it follows you scrolling (Off, Subtle, Medium, Bouncy).
  • Turn footer: under a finished reply, a Copy reply button and how long the turn took; with Claude Code, also, faintly, how fast the model wrote, the tokens the turn used and what it cost; hover for the details.

Improved

1.0.0

The first release of BaoCode: a desktop app for Claude Code, with a fast IDE built in. For macOS (Apple silicon and Intel) and Windows.

Chat

  • Steps fold into single lines, and the current task and its progress stay above the input
  • Review what Claude changed, file by file, and keep or undo it; checkpoints never touch your repository’s .git
  • Give Claude a goal with /goal, and it keeps working until the goal is met
  • A rich-text input: paste images, drop in files, and copy code from the editor as a reference to its lines
  • Edit a message you sent, search your conversations, and see your context and plan usage
  • Run several agents side by side, in tabs or in windows of their own
  • Choose how the commits and pull requests Claude writes are credited

SSH remote projects

  • Open a folder on a Linux host over SSH, as with VS Code’s Remote-SSH: the window stays on your machine, and files, search, Git, terminals, language servers and Claude Code run on the host
  • Pick a host from ~/.ssh/config, or type user@host
  • Claude Code is installed on a host that has none, and your models work there too
  • Reconnects by itself; when a host can’t be reached, you’re told why and can retry

Fast IDE

  • An editor, a terminal and Source Control with a commit graph and Git blame
  • Your VS Code themes, keybindings and language servers
  • Markdown files open as a preview you can edit in place, Typora’s way
  • Commit messages drafted by Claude Code, for you to edit and commit

Models and extensions

  • Use other models through Claude Code: Anthropic’s API, OpenAI’s Chat Completions or Responses, with API keys kept in the system keychain
  • Choose the model for each part of Claude Code’s work, and for titles and commit messages
  • Plugins, MCP servers, skills, subagents, rules, commands and hooks in one place, with your skills from claude.ai

Around the app

  • Notifications, a sound and a count on the app’s icon when an agent needs you; agents keep running in the menu bar or tray when the window is closed
  • Open a folder in BaoCode from Finder or Explorer, and keep a window on top of others
  • In English and Chinese
  • Updates itself in the background, and asks before restarting
