# Goal：Git 功能全面对齐 IntelliJ IDEA，并加上 BaoCode 自己的优化

## 背景
Git 日志和 IDEA 式提交面板已经上线（#328）。用户反馈 IDEA 的 Git「很方便、很好用」，要求逐项对齐，再结合 AI 工作流做我们自己的优化。
本文是对照清单和推进顺序。状态：✅ 已有　🟡 部分有　❌ 没有。每做完一项就在这里改状态。

## 原则
- 交互照 IDEA（键位、命名、默认值），界面用 Bao 自家组件，不用 Flutter 自带 UI。
- 聊天侧边栏和 IDE 共用同一套组件；能在一处做的就不要弹模态框。
- 所有 Git 操作都走 `IdeGitService`，这样本机和 SSH 远程都能用；进行中的操作要能看到，也能取消。

## 我们的优化（IDEA 没有的）
1. **按对话 / 轮次自动生成变更列表**（已完成）：AI 每轮改的文件自动进「AI：<这轮的提问>」变更列表（已在别的列表里的不动），右键「只提交这个变更列表」或「回滚」；改动都提交后列表自动消失。
2. **只提交 AI 改动里认可的部分**（已完成）：改动面板的 diff 里，AI 还没保留的改动所在的块右侧标出「AI · 这轮的提问」（悬停看完整提问，一个文件被几轮改过时列出全部），用户自己改的块不标；再按块 / 按行勾选后提交。目前按文件记轮次，同一文件几轮的改动标的是最近一轮。
3. **AI 提交信息**（已完成）：只依据勾选的文件和块生成（部分提交的文件只给要提交的那部分 diff），并沿用仓库已有的提交风格。
4. **AI 解决冲突**（已完成）：三栏合并里每个冲突块都有「AI 合并」，工具栏还能一次合并全部；结果放进中间栏并用另一种颜色标出，点「应用」才写回。
5. **提交前 AI 审查**（已完成）：输入框旁的审查按钮随时审查要提交的内容（部分提交只审要提交的块）；提交选项里打开「提交前用 AI 审查」后每次提交先审，有错误 / 警告就先拦下，列出问题（点击跳到那一行），可「仍然提交」；没问题直接提交。
6. **问 AI**（已完成）：日志里右键提交「问 AI 这个提交」（多选时一起问）；改动面板里右键文件 / 文件夹「问 AI 这些改动」，冲突文件「让 AI 解决冲突」。请求放进聊天输入框，看过再发；聊天面板没开时自动打开。日志区 diff 里鼠标移到某块上，右侧出现「问 AI 这处改动」，把这块的 diff 连同文件和行号一起放进输入框。
7. **工作树跟着对话走**（已完成）：AI 在哪个工作树，日志就显示哪个；新建工作树后 AI 自动转过去。
8. **不打断**（已评估）：按用户「要 IDEA 那种界面」的要求，起名字（新分支、标签、改名）和危险操作的确认保留 IDEA 式小对话框，不改成 VS Code 式顶部输入框；这些对话框都能纯键盘完成（Enter 确认、Esc 取消）。变基 / 合并 / Cherry-pick 进行中用改动面板顶部横幅、AI 审查结果在提交框下方、Fixup / 克隆的错误都在原处显示，不另外弹窗。
9. **AI 整理分支**（已完成）：交互式变基里「让 AI 整理」，模型按提交内容建议把 wip / 修错字类提交 fixup 进前一个、相关的 squash、信息太空的 reword（直接给出新信息）；建议只填进列表，用户检查后才开始变基。

## 推进顺序
每个阶段都要：实现、补测试、更新本文状态、提交；攒到一定量就发一次测试版。

1. **Diff 查看器**：内联 diff 也能编辑；块旁的回滚 / 搬回；F7 逐块跳转并跨文件；工具栏（并排 / 单栏、忽略空白、高亮粒度、折叠未改动）；改动文件跳转弹窗。
2. **编辑器改动标记**：行号旁的彩条、点击弹出的小 diff、上一处 / 下一处、Annotate 整列。
3. **日志的提交操作**：cherry-pick、revert、reset、改提交信息、fixup / squash / drop、打标签、和本地比较、创建补丁、跳到父 / 子提交、按路径筛选、分支树。
4. **分支操作**：完整的分支弹窗和各项操作；Update Project；推送对话框（含强推）。
5. **冲突**：冲突列表、三栏合并编辑器、进行中操作的横幅、AI 合并。
6. **部分提交与变更列表**：按块勾选（用临时 index 提交）、多个变更列表、AI 按轮次自动建变更列表。
7. **Stash / 搁置**、提交信息历史与检查、作者 / Sign-off / 跳过钩子、.gitignore。
8. **其余**：交互式变基编辑器、远程仓库和标签管理、Clone、提交前 AI 审查。
